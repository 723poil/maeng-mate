# ADR 0007. 앱 내 MCP

상태: 채택

## 맥락

AI 앱에서 본인의 업무와 오늘 근무를 조회한다. AI 연결의 발급·만료·폐기를 앱에서 다루면서 관리 API는 분리한다.

## 결정

- FastMCP Streamable HTTP를 상주 API의 `/mcp/`에 연결하고 lifespan에서 세션 관리자를 시작·정리한다. stateless HTTP이므로 실행 여부와 최근 사용을 표시한다. 설정은 첫 조회 결과와 관리 작업 응답을 유지하며 최근 사용은 `다시 불러오기`로 갱신한다. 같은 목록을 표시하는 동안에는 다음 만료 시각에 도달하거나 시계가 이전 판정 시각보다 앞서면 표시 상태를 다시 확인한다. 만료 배지와 폐기 버튼의 잠금은 기존 행에서 갱신한다. stdio도 유지하며 조회 토큰과 선택 포트만 받아 로컬 API를 호출한다. 두 전송 방식은 같은 조회 포트와 서버 조립 함수를 사용한다. stdio 프로세스와 상주 HTTP 서비스는 각각 실행 중인 도구가 쓰는 루프백 HTTP 클라이언트를 하나씩 소유한다. 각 요청에 인증 헤더를 보내고 쿠키는 보관하지 않으며, 도구 세션이 종료된 뒤 연결 풀을 닫는다. stdio 시작에는 상주 앱이나 Keychain 어댑터가 필요하지 않다. stdout은 MCP 프로토콜 전용이다.
- 관리자 키는 Keychain, MCP 접근 토큰은 SQLite에 해시와 이름·만료·폐기·최근 사용 메타데이터로 저장한다. 원문은 발급 시 한 번 표시하고 닫기·다음 발급·해당 토큰 폐기 시 지운다. 신규 토큰은 `MCP_ACCESS_TOKEN`으로 연결하며 기존 환경 키는 조회 전용 호환 경로를 지원한다.
- MCP 토큰은 `/mcp/`와 지정된 개인 조회 경로에만 허용한다. 설정·인증 관리·근무 정정·발송 경로는 관리자 전용이다. 만료·폐기·사용 상태를 요청마다 확인한다.
- `get_my_system_status`, `get_my_today`, `get_my_workday`, `list_my_task_statuses`, `search_my_tasks`를 제공한다. 근무는 미기록·예정·실제 기록을 구별하고 메모·규칙 원문을 제외한다. 개인 업무·QA 조회는 본인 범위의 모든 원본 상태를 기본으로 포함하며 마감과 원본 키로 정렬한다. 소스 상태 목록과 검색 행에 현재 카테고리 ID와 이름을 제공한다. 검색의 `category_id`는 같은 카테고리의 본인 목록 소스를 선택하며 이름 변경 후에도 유효하다. 이전 호출의 `section` 필터는 기존 구분을 유지한다. 보드 링크 설정은 오늘 조회에서만 다시 읽는다.
- `GET /v1/tasks/statuses`는 조회 토큰에 허용한 읽기 경로로, 설정된 업무·QA 소스별 식별자와 이름, 상태 선택지, 선택지의 근거와 수집 상태를 제공한다. 스키마가 없으면 본인 행에서 관찰한 상태를 사용한다. AI는 의미로 요청한 상태를 소스별 선택지와 대조하고, 해당 `source_id`와 정확한 상태 이름을 `POST /v1/tasks/search` 본문으로 전달한다. 여러 이름은 합집합으로, 미지정은 `include_unset`으로 선택한다. 검색은 설정된 본인 조회 범위 안에서만 소스를 좁힐 수 있다. 한 페이지는 최대 100건이며 0 이상의 정수 위치를 받는다. 같은 스냅샷과 검색 조건에서 반환된 `nextOffset`으로 마지막 행까지 이어 읽을 수 있고, 마지막 페이지에서는 `null`을 반환한다.
- Codex와 Claude Code용 스킬은 개인 스킬 경로에 설치한다. 선택된 모든 대상의 기존 설치 해시를 먼저 검증한다. 내용과 권한(600)이 같은 파일은 유지하고, 설치가 실패하면 이번에 교체한 파일과 만든 빈 폴더를 역순으로 정리한다. 사용자 수정본은 보존한다. 설치는 조회 지침을 복사하며 MCP 연결 등록은 사용자가 별도로 설정한다.
- 스킬 배포 번호는 `src/infrastructure/skill_bundle.py`의 `SKILL_VERSION`에서 앱과 독립적으로 관리한다. 첫 번호는 `1.0.0`이며 동봉 지침이나 AI 메타데이터를 변경해 배포할 때 주·부·패치 번호 중 하나를 올린다. 설치 기록의 `version`은 파일 형식이고, 형식 2의 `skillVersion`은 설치한 스킬 버전이다. 형식 1은 버전 미기록으로 표시하고 다음 설치 때 기존 해시를 검증한 뒤 이전한다. MCP 설정에서 대상별 설치 버전과 업데이트 가능 여부를 확인하고 명시적으로 재설치한다. 선택한 대상 중 더 높은 버전이 있으면 모두 보존한다.

## 결과와 검증

### 명시적 목록 소스 접근

사용자 정의 목록은 담당자·개인 ID와 무관하게 AI에 필요한 자료를 제공한다. 화면의 `내 항목만 보기`, 카드의 표시·숨김 규칙, 캘린더 표시 여부는 접근 정책이 아니므로 목록 MCP에 암묵적으로 적용하지 않는다. 기존 개인·일정 도구의 의미는 유지한다.

- 첫 범위는 `task` 목록 소스다. `list_sources`, `search_items`를 별도 HTTP 주소 `/mcp-lists/`와 stdio `MCP_QUERY_MODE=lists`로 제공한다. 기존 `/mcp/`·기본 stdio의 다섯 개인 도구는 그대로 유지한다. 일반 상태의 `configuration.personalIdentity`는 ID 원문 없이 설정 여부만 제공하며 목록 조회의 전제가 아니다.
- 소유자는 관리자 전용 `/v1/mcp/list-access/` 또는 `settings mcp-lists`에서 현재 소스와 칼럼을 선택한다. 발급 요청에는 `allRows=true`를 명시한다. 토큰은 선택한 소스 전체 행과 선택한 칼럼만 허용하며, 카테고리의 나중 멤버나 새 칼럼을 자동 포함하지 않는다. 이름·유효 기간·폐기·최근 사용을 관리하고 원문은 발급 때 한 번만 반환한다. 네이티브 선택 편집기는 후속 범위다.
- 관리 CLI의 프로필은 실행 파일로 결정한다. 소스 `uv run`은 개발 프로필이며 배포 앱은 `Contents/MacOS/MaengMate`를 직접 실행한다. 업데이트 공개키가 있는 동봉 실행본만 배포 프로필이다. 관리 명령은 프로필별 시작 파일의 포트와 Keychain 관리 인증을 사용한다. stdio는 이 둘을 읽지 않고 소비자 토큰과 명시 포트 또는 실행 프로필의 기본 포트를 사용한다. 관리 키를 복사해 프로필 차이를 우회하지 않는다. 임시 프로필·가상 Keychain 경계에서 실제 CLI 수명과 stdio를 검증하되 frozen 분기 모사와 실제 배포 바이너리 검증을 구별한다.
- SQLite v19의 `mcp_list_tokens`는 기존 개인 토큰 해시 테이블과 분리한다. 기존 토큰에는 새 권한이 없으며 목록 토큰에도 개인·출퇴근·일정·관리 API 권한이 없다. 구버전 앱도 새 토큰을 기존 테이블에서 찾을 수 없다. 전체 MCP 중지, 만료·폐기는 매 요청에 판정한다.
- 내장 목록 MCP는 현재 HTTP 요청의 소비자 인증을 조회에 전달한다. 기존 개인 MCP의 내부 관리자 클라이언트를 재사용하거나 공유 클라이언트의 인증 헤더를 변경하지 않는다. stdio는 소비자 토큰으로 같은 목록 전용 HTTP 조회 경로를 사용한다. 직접 HTTP 호출에도 같은 권한 검사를 적용한다.
- 발급 범위는 원본·프로바이더·소스 종류·카테고리 정체성과 칼럼별 원본 연결·종류를 고정한다. 원본이나 카테고리가 바뀌면 해당 소스를 제외하고 `source_binding_changed`를 표시한다. 칼럼 연결 변경·미수집은 그 칼럼을 `available=false`로 표시하며 다른 허용 칼럼과 행은 보존한다. 담당자 연결 제거 자체가 다른 칼럼 조회를 막지 않는다. 허용 범위 확대는 폐기 후 새 발급으로 수행한다.
- 검색 조건은 호출자가 명시할 때만 적용한다. 제목·원본 상태·기한·담당자 참조 조건은 그 칼럼이 허용되고 연결돼 있을 때만 사용한다. 조건을 평가할 수 없으면 입력 오류로 알리며 조건을 몰래 제거하지 않는다. 담당자 없는 목록도 조건을 생략하면 허용한 모든 행을 읽는다. 기본 50개·최대 100개와 `nextOffset`을 사용하고 건수는 권한·요청 조건 적용 뒤 센다. 정렬은 허용되지 않은 값에 의존하지 않는 소스·항목 키 순서다.
- Notion 수집 요청은 담당자·메인 카드 필터를 보내지 않고 모든 정상 행을 저장한다. 따라서 행 범위를 넓히는 수집 변경은 필요하지 않다. 기존 저장 칼럼의 문자열 미리보기는 공백 축약·생략·분류 결과여서 원형으로 재해석할 수 없다. 목록의 이미 연결한 저장 칼럼에 `raw_fields`를 추가해 원본 문자, 숫자, 불리언, 선택 배열, 날짜 구간과 사람 참조를 타입별로 보존한다. 사람 전체 객체나 원본 Notion JSON은 저장하지 않는다. 수집 지문으로 다음 정상 수집을 앞당기되 부분 실패 시 이전 정상 스냅샷을 유지한다.
- 구 스냅샷의 원형 칼럼은 다음 정상 수집 전까지 `raw_field_not_collected`다. 제목·상태·기한 등 기존 구조화 값은 즉시 조회할 수 있다. 시간·신선도·매핑 불일치는 수집 근거와 함께 제공한다. 표시용 분류·관련성 판정은 AI가 원본 값으로 판단하며 허용되지 않은 칼럼은 값·조건·정렬에 사용하지 않는다.
- 백업의 기기 접근 제외 목록에 새 테이블을 포함한다. v17·v18 백업은 업무 행을 보존하고 빈 목록 접근 테이블로 이전한다. 전체 복원에서는 현재 기기의 토큰·폐기 상태를 보존하며 복원된 소스·칼럼 연결과 다시 대조한다. 토큰 원문은 백업하지 않는다.
- 실제 저장·통신·디코딩 실패는 정상 빈 결과로 바꾸지 않는다. 관리자 인증·조회 인증·입력 오류도 구별한다. 읽기는 수집·출퇴근·알림 기록을 만들지 않으며 인증의 최근 사용 메타데이터만 갱신한다.

구현은 `application/mcp_lists.py`, `presentation/mcp_lists.py`, `mcp_lists_http.py`, `infrastructure/sqlite/mcp_lists.py`와 부트스트랩에 둔다. 검증은 임시 SQLite·가상 원천·실제 개발 API 프로세스에서 두 MCP 전송, 본인/담당자 연결 부재, 원형 값 보존, 허용 범위, 폐기, 오류 전달과 조회 전후 업무 저장 상태를 확인한다. 운영 계정 검증과 구별한다. 일반 일정·휴가·출퇴근, 임의 칼럼 검색 연산자, 네이티브 권한 편집기는 이 첫 범위에 포함하지 않는다.

개인 업무 검색 도구 `search_my_tasks`는 SDK가 문자열을 JSON으로 다시 해석하기 전에 선언된 필드와 JSON 타입을 검사한다. HTTP와 같은 `TaskSearch.parse`가 범위와 기본값을 적용하며 잘못된 입력은 조회 포트 호출 전에 거부한다. 문자열 검색어 `"null"`도 그대로 보존한다.

AI에서 조회해도 수집이나 알림이 시작되지 않는다. `src/presentation/mcp.py`, `src/application/mcp_access.py`, `src/bootstrap/wiring.py`, `src/infrastructure/ai_skills.py`에서 구현한다. 만료·폐기·관리 경로 차단, stdio 호환과 스킬 재설치를 확인한다.
