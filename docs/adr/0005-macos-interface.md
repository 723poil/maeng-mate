# ADR 0005. macOS 화면

상태: 채택

## 맥락

사용자가 메뉴바 한 화면에서 근무·수집·업무를 빠르게 조작하고, 설정에서는 표시와 전달을 독립적으로 관리한다.

## 결정

- Finder 또는 메뉴바 패널 상단의 홈 열기 버튼으로 같은 메인 창을 열고, 홈과 큰 캘린더를 전환한다. 사이드바는 설정과 같은 네이티브 소스 목록을 쓰고 제목 막대의 사이드바 아이콘으로 접는다. 0.2초 동안 사이드바와 본문을 함께 전환하고, 도중에 다시 누르면 현재 위치에서 반전한다. 움직임 줄이기에서는 즉시 전환한다. 홈의 모든 카드는 스크롤 본문 폭을 공유하고 메뉴바 달력만 패널 안쪽 여백을 둔다. 홈은 확인된 화면 설정의 순서와 표시 선택을 사용한다. 선택된 근무·캘린더 기능 및 연결된 카테고리만 나타내고, 본문이 여러 영역이면 목차도 같은 순서로 만든다. 큰 캘린더의 표시 선택과 날짜는 메뉴바 달력과 공유한다. 설정은 기존 창을 재사용하고 화면 설정 버튼은 해당 페이지를 직접 연다.

- 신규 설치는 카테고리가 없는 상태에서 시작한다. 각 화면의 카테고리 이름·표시 여부·순서는 사용자 설정을 따른다. 카테고리가 없거나 모두 숨겨져 있으면 카테고리 영역을 비워 둔다. 메인 목록과 캘린더는 각자의 표시 설정을 적용한다.

- 메뉴바 패널은 앱을 활성화하지 않는 패널(`NSWindowStyleMaskNonactivatingPanel`)로 연다. macOS의 협력형 활성화는 다른 앱이 앞에 있을 때 활성화 요청을 거절할 수 있고, 비활성 시 숨김을 켠 패널은 그때 바로 사라져 Dock을 먼저 눌러야 열렸다. 패널은 비활성 앱에서도 키 창이 되어 입력을 받고, 바깥 클릭·키 창 해제·앱 비활성화로 닫는다. 열 때는 키보드 초점을 비워 출근 시각이 저절로 선택되지 않게 한다. 시간 입력은 Return을 스스로 처리하지 않으므로 패널이 Return과, 초점을 받지 않는 곳(배경·글자·버튼) 클릭을 편집 종료로 처리한다. 구현은 `src/presentation/glass_panel.py`다.
- 설정 카드는 `src/presentation/native_views.py`의 간격 체계를 따른다. 페이지 좌우와 카드 안쪽 여백 16, 카드 사이 12, 제목 줄 20, 왼쪽 항목 이름 칸 112다. 입력 줄은 시스템 설정의 묶음 목록처럼 위아래 여백을 포함한 44pt이고 줄끼리 맞붙어 경계에 구분선만 긋는다. 컨트롤은 `form_control_y`로 줄 세로 가운데에 놓고, 마지막 줄 아래는 4pt만 더한다. 불투명 화면의 카드는 테두리 없이 글자색 3.5%를 깔아 배경보다 한 단계만 밝거나 어둡게 한다. 입력·체크박스는 항목 이름 칸 뒤 같은 x에서 시작하고, 카드 제목 줄 오른쪽 버튼은 안쪽 여백에 맞춘다. 카드 높이와 줄 위치는 `card_height`·`form_row_y`로 계산한다. 근무 규칙과 알림 페이지가 이 체계를 적용했다. 카드 안 입력 줄 사이에는 줄 간격 가운데에 안쪽 여백 폭의 구분선을 긋는다(`form_dividers`). 여러 개를 켜고 끄는 선택(근무 요일)은 공통 선택 칩(`Chip`, 높이 22·모서리 6·12pt 중간 굵기, 켜짐은 강조색)으로, 하나를 고르는 선택(퇴근 알림 시각)은 기본 선택 메뉴로, 상태 배지는 글자 폭에 맞춰 줄어드는 `SettingsBadge`로 그린다. 테두리 있는 버튼의 오른쪽 끝은 6pt 바깥으로 밀어 스위치와 같은 선에 맞춘다.
- 알림 페이지는 ‘알림’(사용 스위치·macOS 권한 배지와 알림 확인), ‘전달 채널’(채널별 스위치), ‘퇴근 알림’(시각 선택 메뉴), 카테고리별 규칙 카드 순서다. 카테고리로 이동만 하던 안내 카드는 사이드바와 겹쳐 없앴고, 규칙이 하나도 없을 때만 규칙을 만드는 곳을 한 줄로 알려 준다.
- 설정 사이드바 맨 위의 ‘앱 정보’에 앱 아이콘·이름·버전(개발 실행본은 ‘개발용’)과 ‘업데이트 확인…’을 가운데 정렬로 둔다. 버전과 업데이트 버튼은 사이드바 아래에 두지 않는다. 이 페이지는 저장 설정이 없으므로 ‘다시 불러오기’와 저장 상태를 숨긴다.
- 메뉴바에는 앱 아이콘의 고양이 머리를 단색 템플릿으로 옮긴 표시를 사용한다. 눈은 투명하게 뚫고 앱 아이콘보다 조금 작게 줄여 작은 크기에서 날카로워 보이지 않게 한다. 꼬리는 작은 크기에서 몸과 붙어 보여 생략한다. 개발용도 같은 표시를 쓴다. 개발 앱만 도움말·VoiceOver 이름과 설정 ‘앱 정보’의 버전 옆에 ‘개발용’을 표시한다. macOS가 배경과 선택 상태에 맞춰 색을 정한다. 수집·연결 상태는 버튼 도움말, VoiceOver 이름과 패널의 수집 카드에서 확인한다. 수집 중에는 내부 데스크톱 상태에서 받은 소스 키로 활성 설정의 소스 이름을 표시하고, 이름이 없으면 카테고리 이름을 사용한다. 열린 패널은 수집 중 2초 뒤에 다시 조회해 대상 전환과 종료를 반영한다.

- 카테고리의 `설정…` 시트는 저장 칼럼, 메인 목록, 캘린더, 알림 규칙을 나눠 표시한다. 캘린더 날짜와 알림에서 카테고리의 저장 칼럼을 고른다. 수집 소스의 `연결 편집` 시트는 카테고리의 값 종류와 호환되는 원본 속성을 보여 준다. 소스 연결의 적용은 저장 초안에 반영하고 취소는 이전 연결을 유지한다.
- 카테고리 설정 탭은 macOS 세그먼트 컨트롤로 전환한다. 알림 규칙 탭에는 등록한 이벤트 규칙과 칼럼 값 변경 규칙이 함께 나온다. 새 규칙과 기존 규칙의 편집은 같은 모달 시트에서 연다. 이름, 발송 시점, 항목의 포함·제외 조건, 문구, 채널과 사용 여부를 함께 편집한다. 적용은 전체 입력을 검증해 목록 초안에 반영하고, 취소는 편집 전 규칙을 유지한다. 카테고리를 저장할 때 목록을 확정한다.
- 메인 목록 탭은 표시 필터·숨김 조건·정렬 순서를 나눠 편집한다. 새 카드는 세 목록이 비어 있으며, 기존 카드에서 이전한 조건도 같은 행에서 수정하거나 삭제한다. 숨김 조건 중 하나라도 일치하는 행은 표시에서 제외한다. 필터는 선택한 칼럼의 값 종류에 맞는 연산자와 입력을 보여 준다. 새 표시 필터는 해당 카테고리의 소스 한 곳 이상에 연결한 저장 칼럼에서 고른다. 연결 칼럼이 없으면 추가 버튼을 끈다. 같은 칼럼을 여러 행에서 비교할 수 있으며 기존 내장 조건과 연결 해제된 저장 칼럼은 해당 행에서 유지하거나 연결 칼럼으로 바꿀 수 있다. 정렬은 위에서부터 적용하며 행을 이동해 우선순위를 바꾼다. 규칙 모두 지우기도 저장 전까지는 편집 초안에만 적용한다.
- 소스 연결 시트도 세그먼트 컨트롤로 카테고리 칼럼과 수집에 사용할 속성을 전환한다. 저장 칼럼의 `추가 표시` 옆 물음표는 칼럼의 표시 위치와 숨긴 칼럼의 용도를 설명하고, `표시 예시` 라벨로 샘플을 구분한다.
- 연결 편집은 ‘수집에 사용할 속성’으로 열고, ‘분류 기준’, ‘카테고리 칼럼 연결’ 순서로 배치한다. 원본 속성의 역할을 정한 뒤 값의 분류를 설정하고, 카테고리에서 공유할 추가 칼럼을 연결한다. ‘분류 기준’에서 실제 원본 칼럼과 원본 값별 분류 이름, 규칙에 없는 값의 기본 이름을 편집한다. 같은 카테고리의 표도 각각 다른 규칙을 가진다. ‘수집에 사용할 속성’의 업무·QA 완료, 일정 알림 유형, 휴가 승인 판정은 해당 속성 아래에서 원본 값별로 설정한다.

- 테두리 없는 투명 `NSPanel`에 macOS 26 `NSGlassEffectView`를 직접 배치한다. 창 그림자·중첩 팝오버·별도 화살표를 없애고 콘텐츠 레이어의 배경과 모서리를 일치시킨다. 읽기 영역의 카드는 유리를 덮지 않고 비쳐 보이게 옅게 칠한다. 어두운 모드는 검정 22%, 밝은 모드는 흰색 45%를 얹어 유리 위에 한 겹 더 흐린 층처럼 보이게 하고, 글자색 12%의 얇은 테두리로 경계를 남긴다. 메인 창·출퇴근 기록 창 같은 유리 창의 카드도 같은 바탕(`card(..., glass=True)`)을 쓴다. 설정 창은 시스템 설정처럼 왼쪽 사이드바만 바탕화면이 비치는 사이드바 재질로 두고 본문은 불투명한 창 배경을 쓴다. 그 위 카드와 시트·팝오버의 카드는 글자색 5%를 깔고 시스템 구분선 색 테두리로 배경과 한 단계만 구분한다.
- 메뉴바 버튼을 기준으로 상단·좌우 위치를 고정한다. 목록 확대·축소 때 문서 높이를 바꾸고 읽던 위치를 보존한다. 높이만 바뀔 때는 기존 행을 위쪽에 고정해 재사용한다. 조회 결과가 바뀌면 같은 순번의 표시값과 링크를 비교해 달라진 행의 컨트롤만 다시 만든다. 가로 폭이 바뀌면 배지와 텍스트를 새 너비에 맞춰 배치한다. 카드 순서는 전환 시작 때 정하고 애니메이션 프레임마다 재사용한다. 설정에서 숨긴 카드는 보관하고, 연결 소스가 사라진 카드는 뷰에서 제거한다. 각 행 버튼에 원본 링크를 연결하므로 다른 카드의 행 개수가 달라져도 링크 순번을 다시 매기지 않는다. 반복 조작·닫기·재열기 때 전환 상태를 정리한다. 움직임 줄이기를 지원한다. 목록 행은 해당 소스의 설정에 따라 상태·기한 또는 차시·제목을 한 줄에 표시한다. 부모 제목 표시를 켜면 기본 행과 사용자 지정 칼럼 행 모두 업무 제목 앞에 부모 제목을 붙인다. 기본 행의 기한은 별도로 유지한다. 부모 제목은 남은 폭의 3분의 1과 120pt 중 작은 폭에서 말줄임하고 도움말에 전체 값을 표시한다. 차시만 저장된 이전 스냅샷도 현재 소스의 부모 제목 표시 설정을 따른다.
- 저장 칼럼의 ‘메뉴바 표시’는 자동·텍스트·상태 배지 중에서 고른다. 자동은 원본 상태 타입이나 업무 상태에 연결한 칼럼에 기존 상태 색상을 사용한다. 이름과 값으로 상태를 추측하지 않는다. 메뉴바와 달력 응답은 표시 칼럼에만 배지 표식을 넣는다. 달력의 선택 날짜 상세는 시간 옆에 메인 목록과 같은 배지를 놓는다. 공간이 부족해도 아래 상세에서 모든 표시 칼럼의 이름과 값을 지정한 순서로 확인할 수 있다. 행의 앞쪽에 비어 있지 않은 배지를 놓고 제목에 필요한 폭이 부족하면 나머지 값은 텍스트로 표시한다. 전체 이름과 값은 행 도움말에서 확인한다.
- 근무 카드는 퇴근 시각을 크게 두고 바로 뒤에 ‘퇴근 예정’을 붙인다. 그 아래 ‘출근 09:00 · 일반 근무’ 한 줄로 입력을 둔다. 출근 시각은 테두리 없는 기본 macOS 시간 입력(`NSDatePicker` 텍스트형)이라 평소에는 글자처럼 보이고, 누른 시·분만 선택되어 숫자 입력과 방향키로 고친다. 퇴근 예정과 같은 24시간 표기와 고정폭 숫자를 쓴다. 근무 형태는 테두리 없는 선택 메뉴이며 휴가가 없는 날은 앞의 ‘출근’과 겹치지 않게 이 화면에서만 ‘일반 근무’로 부른다. 연차인 날은 출근을 기록하지 않으므로 이 메뉴에서 고를 수 없고 월별 기록 창에서 정한다. 기록 창에서 연차로 정한 날은 같은 메뉴에 ‘연차’로 표시한다. macOS에는 시간 휠이 없어 별도 시간 선택 부품을 만들지 않는다. 큰 표시는 `설정 → 화면 → 근무 카드`의 ‘퇴근 표시’로 퇴근 시각 또는 남은 시간(‘2시간 13분 퇴근까지’, 분 단위 올림, 1분마다 갱신)을 고른다. 메뉴바에서 큰 표시를 누르면 같은 설정을 바꿔 저장한다. 실제 퇴근을 기록했거나 예정 시각이 지나면 남은 시간 대신 시각을 표시한다. 미기록·저장됨 같은 평상시 상태 문구는 표시하지 않는다. 아직 기록하지 않은 날의 퇴근 예정은 흐린 색으로 구분하고, 저장 실패·기록 충돌·휴무처럼 사용자가 알아야 하는 안내만 카드 제목 옆에 표시한다.
- 수집 소스가 하나도 없으면 상태 줄(상태 아이콘·제목·수집 시각·수집 주기)을 모두 숨기고 그 자리 왼쪽에 ‘Notion 연결…’ 버튼만 둔다. 토큰이 없으면 설정의 Notion 페이지를, 있으면 수집 소스 페이지를 연다. 새로고침·집계·주기 저장은 비동기로 진행 상태를 보여주며 기존 목록과 미저장 입력을 유지한다. 새로고침은 저장 자료를 다시 읽는다.
- 설정 사이드바와 창은 `SettingsPage`로 페이지를 식별한다. 일부 연동을 사용할 수 없어 목록 순서가 달라져도 재조회·저장·다시 시작은 선택된 페이지에 연결된다. 화면 표시·드래그 순서는 내부 정렬과 독립적이다. 전체 알림·각 채널·종류는 스위치로, 퇴근 시각은 복수 선택으로 관리한다. 설정의 조회 재시도는 단조 시계 기준 1초부터 최대 30초까지 대기를 늘린다. 메뉴바는 활성 설정 제어기 목록을 갱신·종료 대기·정리에 함께 사용한다. 초기 조회 실패는 재시도하지만 불명확한 저장·충돌은 초안을 유지한다.
- 설정 적용·백업 복원·업데이트로 앱을 다시 시작하기 전에 모든 탭의 미적용 초안과 진행 중인 저장을 같은 기준으로 확인한다. 알림 발신 이름·아이콘은 `NotificationIdentityView.dirty`도 공통 판정에 포함하며, 소스·카테고리·근무 규칙·Notion 설정의 재시작 버튼과 실행 경로에서 함께 검사한다. 적용이 확인되어 초안이 해소되면 저장된 설정의 재시작 요구는 허용한다.
- 시스템 글꼴의 실제 크기를 측정해 입력·행·배지를 가운데 맞춘다. 등록 배지는 공통 `SettingsBadge`와 `registration_status`를 사용한다. 등록 파랑·확인 초록·미등록 회색·실패 빨강·응답 지연과 요청 제한 주황으로 구분한다. 편집 키 조합은 현재 Cocoa 편집기에 전달하며 한글 입력 상태에서도 붙여넣기를 지원한다.

- 작은 달력 카드는 왼쪽에 월 제목, 오른쪽에 ‹ 오늘 › 이동 묶음과 표시 항목·큰 캘린더 아이콘만 둔다. 새로고침은 패널 머리의 새로고침이 달력까지 다시 읽는다. 색은 의미가 있을 때만 쓴다. 일요일은 빨강, 토요일은 파랑으로 요일 머리와 날짜를 표시하고 다른 달 날짜는 같은 색을 흐리게 쓰며, 오늘은 시스템 강조색 원, 선택한 다른 날은 같은 크기의 회색 원으로 표시한다. 큰 달력은 선택한 칸 전체를 옅게 칠한다. 선택 날짜 요약은 ‘11월 16일 월요일’ 제목과 일정 두 줄이며, 일정이 없으면 조회 안내나 ‘일정 없음’을 회색으로 쓴다.
- 달력 월 이동은 백그라운드에서 조회하고 완료 신호를 메인 스레드에서 반영한다. 작은 달력과 별도 창은 요일 헤더와 42개 날짜 칸·버튼을 재사용한다. 월이나 필터가 바뀌면 날짜·일정·도움말을 갱신하고, 같은 월에서 날짜만 선택하면 선택 배경을 옮긴다. 대기 중에는 날짜 버튼만 잠그고, 숨은 격자는 다시 보일 때 갱신한다. 두 달력은 소스 표시 설정이 바뀔 때 만든 필터 목록을 공유한다. 닫힌 필터 팝오버는 열기 직전에 최신 선택을 읽고, 열린 필터는 목록·선택·입력 가능 여부·시스템 외관이 바뀔 때 갱신한다.

- 설정·출퇴근 기록·캘린더 독립 창은 투명 제목 막대 왼쪽의 macOS 표준 닫기 버튼을 사용한다. ⌘W와 버튼은 같은 창을 닫고, 다시 열면 선택과 편집 초안을 보존한다. 설정을 닫을 때 일회성 인증 표시는 지운다.
- 설정·출퇴근 창을 닫으면 주기적인 화면 갱신은 멈춘다. 진행 중인 저장·조회와 후속 설정 동기화는 마무리하고, 창을 다시 열 때 최신 결과와 초안을 표시한다.

## 결과와 검증

알림 이름·아이콘의 편집·적용 확인 전후와 저장값으로 되돌린 초안을 임시 SQLite와 네이티브 설정 컨트롤에서 확인한다. 소스·카테고리·근무 규칙·Notion의 버튼과 직접 액션이 같은 차단 상태를 사용하고, 저장된 소스의 재시작 요구만 남으면 다시 시작할 수 있어야 한다.

화면 영역을 숨겨도 수집·근무·알림 구독은 유지된다. `src/presentation/menubar.py`, `glass_panel.py`, `entry_section.py`, `preferences_window.py`를 기준으로 실제 앱에서 밝은·어두운 외관, 확대 재열기, 스크롤, 키 입력과 화면 경계를 확인한다.
