# ADR 0003. 개인 업무 조회와 캘린더

상태: 채택

## 맥락

오늘 해야 할 일을 추리는 목록과 날짜를 탐색하는 월 달력은 목적이 다르다. 같은 저장 자료를 읽더라도 표시 기준을 각 화면에 맞게 적용한다.

## 결정

HTTP·MCP·메뉴바는 application의 `date_inputs`로 날짜와 월을 검증한다. 오늘 목록·메뉴바·검색은 소스별 저장 버전과 읽기 매핑이 같으면 복원본을 공유한다. 소스별로 현재 버전의 일반·메뉴바 칼럼 선택을 최대 두 형태만 보관하며, 요청한 소스만 원래 순서로 반환한다. 변경된 원본 JSON은 읽기 트랜잭션 안에서 한 행씩 복원한다. 버전은 요청마다 DB에서 확인하고 날짜·검색 조건·신선도는 그때 다시 계산한다. 오늘 목록과 검색은 스냅샷에 대응하는 소스 설정을 항목 표시까지 전달해 해당 소스의 섹션과 원본 상태를 보존한다.

- 본인 ID와 현재 설정 소스로 조회 범위를 제한한다. 담당 여부와 참여 범위는 관련성 전략으로 구분한다. 매핑 불일치·미수집·지연·잘림을 응답에 표시한다. 현재 스냅샷을 서울 날짜에 투영하며 과거 상태를 복원하지 않는다.
- 개인 오늘 조회와 검색의 업무·QA는 본인에게 관련된 현재 행을 원본 상태 그대로 제공한다. 오래된 완료 업무와 메뉴바에서 숨긴 QA도 검색할 수 있다. 마감과 원본 키로 정렬하고 회의·휴가의 날짜 및 취소 필터는 유지한다. 이전 완료 기준은 기존 메인 카드의 표시 조건 계산에서만 해석한다.
- `카테고리`에서 등록한 항목을 `수집 소스`에서 선택한다. 같은 카테고리를 고른 표는 메인에서 카드 하나로 묶는다. 메인 카드에서 정렬을 지정하지 않으면 연결한 소스 순서대로 읽은 행을 표시한다. 카드와 소스에 명시한 정렬이 없으면 하위 표 안에서 부모 숫자 칼럼이나 제목에서 추출한 차수를 내림차순으로 정렬한다. 빈 값은 끝에 둔다. 카드 정렬이 있으면 사용자가 원하는 위치에 ‘부모 정렬값’을 추가한다. 소스에서 직접 선택한 날짜순·제목순은 그 소스 안에서 적용한다. `화면`에는 근무·캘린더와 현재 소스에 연결된 카드가 표시되며 각 카드의 위치와 표시 여부를 변경할 수 있다. 이름을 바꿔도 카테고리 ID와 화면 설정은 유지한다. 카드에 원본 표가 여러 개면 각 항목에서 해당 원본을 연다.
- 메인 카드 규칙은 카테고리의 선택 설정인 `configuration.mainList`에 보관한다. 제목·상태·QA 차시·기한 또는 일정 시작일·최종 수정일·완료 여부와 저장 칼럼 ID를 조건 및 정렬에 사용할 수 있다. 숨김 조건 중 하나에 일치하는 행을 제외한 뒤, 표시 조건을 모두 만족하거나 하나 이상 만족한 행을 고른다. 연결된 표의 행을 합쳐 정렬한 뒤 미리보기 개수를 제한한다. 표시 칼럼의 라벨과 값은 이 순서에서 미리보기에 넣을 후보에만 붙이며, 칼럼까지 포함한 JSON 크기로 카드별 한도를 적용한다. 동률은 다음 정렬 기준을 따른다. 텍스트 값의 순서를 지정하면 목록에 없는 값은 지정값 뒤에 놓는다. 일반 정렬은 빈 값을 마지막에 둔다. 이전한 원본 날짜순은 당시의 ISO 날짜·시각 순서와 빈 날짜 처리 방식을 유지한다.
- 업무·QA 카드의 ‘업무 분류 (수집 소스)’는 해당 소스에서 선택한 칼럼과 값별 이름을 비교한다. 완료 체크는 완료 관련 필터에만 사용한다. 업무 소스의 제목순·날짜순에서 동률이면 원본 조회 순서를 유지한다. 분류와 정렬 순서는 독립적으로 편집할 수 있다.
- 메인 카드는 표시 필터와 숨김 조건이 모두 비어 있으면 소스의 사람 범위 안에 있는 모든 스냅샷 행을 표시한다. 오래된 완료 업무·QA·다른 날짜의 일정도 포함하며 취소 일정은 취소로 표시한다. 오늘에 걸친 일정, 일정 취소 여부, 조회일 기준 N일 전부터의 날짜 등은 사용자가 필터로 선택한다. 기존 카드가 사용한 완료 업무의 기한, QA의 상태·종료 차시·최종 수정일, 당일·취소 일정의 조건과 정렬은 최초 이전 시 일반 규칙으로 저장한다. 새 카드는 빈 규칙으로 시작한다. 기간 조건은 서울 날짜 기준으로 오늘을 포함하며, 숨긴 저장 칼럼도 내부에서 비교한다. 규칙에서 참조하는 텍스트 칼럼은 다음 수집부터 전체 값을 비교하며 화면에는 앞 240자를 표시한다. 일반 오늘 조회·검색·캘린더에는 메인 카드 규칙을 주입하지 않는다.
- 검색은 제목·상태·기한·섹션을 검사하고 결과 제한 전에 필터링한다. `POST /v1/tasks/search`의 본문으로 검색어를 넘겨 URL 로그에 남기지 않는다. 기본 50건·최대 100건과 `nextOffset`을 제공한다. 표별 원본 상태 이름은 정확히 비교하고 여러 상태는 하나라도 일치하면 선택한다. 표 ID는 허용된 개인 소스 집합을 좁히는 데만 쓴다. 상태 미지정은 별도 조건으로 조회하며 전체 일치 건수는 페이지 밖의 행까지 센다. 앞쪽 페이지는 업무와 QA를 함께 순회하며 페이지 끝 순위까지만 보관한다. 뒤쪽 페이지가 원본 행 수의 절반 이상을 포함하면 전체 정렬을 사용하고, 시작 위치가 원본 행 수를 넘으면 행을 보관하지 않는다.
- `GET /v1/calendar`는 본인 스냅샷과 근무 기록을 42일 격자에 투영한다. 월 조회에는 소스 매핑·표시 여부·색상·카테고리를 전달한다. 서버는 표시 소스의 마지막 성공 실행 ID·종류·매핑으로 일정 버전을 구분한다. 수집 시작·실패·예약 변경 시에는 최신 헤더만 읽고 마지막 일정 투영을 월 간에 재사용한다. 버전과 변경된 원문은 같은 읽기 트랜잭션에서 확인하고, 근무 기록과 신선도는 요청마다 갱신한다. 업무·QA의 완료·보류·차시 필터는 적용하지 않는다. 월별 결과의 HTTP 직렬화와 상세 응답 크기 제한은 표현 계층에서 처리한다. 상세 칼럼은 JSON 이스케이프를 포함한 길이를 누적하다가 남은 한도를 넘으면 해당 행의 상세만 비운다. 그 행의 예산은 차감하지 않아 뒤에 오는 짧은 상세를 표시할 수 있다. 기간은 시작과 기한으로, 단일 날짜는 기한으로 표시한다. 날짜 전용 종료는 포함하고 회의 등의 시점 구간에서 자정 종료는 다음 날짜에 중복 표시하지 않는다.
- 메인 작은 달력과 별도 창은 날짜·데이터·표시 설정을 공유한다. 월 응답이나 필터를 바꾸면 현재 42일과 겹치는 일정만 날짜별로 묶는다. 두 격자와 선택 날짜 상세는 이 목록과 같은 출근 기록을 사용한다. 표시 대상은 출근 기록과 캘린더 표시를 켠 소스의 카테고리다. 메인 표시는 기본 숨김이며 상단 버튼으로 언제든 별도 창을 연다. 메인 필터 팝오버는 부모와 함께 닫힌다. 숨긴 카테고리는 `app_preferences.calendar.hiddenCategories`에 ID로 보존한다. 출퇴근은 날짜의 아이콘과 상세로 표시한다.
- 카테고리에서 지정한 캘린더 색상과 표시 여부를 두 달력에서 공유한다. 날짜 기준으로 카테고리 칼럼을 고르면 각 소스에 연결한 날짜를 쓴다. `소스의 일정·기한 사용`은 수집 소스에서 일정이나 기한으로 연결한 날짜를 쓴다. 메인 영역이 숨겨져 있어도 캘린더에 표시할 수 있다.
- 메뉴바와 달력의 기본 일정 표시에는 소스에서 분류로 연결한 속성값을 사용한다. 회의·휴가·기타의 의미 분류와 카드의 카테고리 ID는 원본 분류명과 별도로 유지한다. 표시 칼럼을 직접 고르면 메뉴바 목록의 제목 뒤에 선택한 값만 지정한 순서대로 표시한다. 칼럼 이름은 행 도움말과 캘린더 상세에서 값과 함께 표시한다. 연결한 표시 칼럼을 전부 끄면 메뉴바에는 제목만 남고 달력 상세와 도움말에서도 상태 표시를 생략한다. 직접 표시 칼럼의 원본 값은 관리자 조회에만 포함한다. 칼럼 이름과 순서만 바꾸면 수집 스냅샷을 재사용한다.

## 결과와 검증

일시적인 표시 설정과 조회 요청은 수집·발송·근무 기록을 바꾸지 않는다. `src/application/use_cases/get_my_today.py`, `src/application/use_cases/search_my_tasks.py`, `src/application/calendar.py`, `src/presentation/calendar_views.py`에서 구현한다. 날짜 경계·종류 전환·두 화면의 필터 공유·원본 이동을 확인한다.
