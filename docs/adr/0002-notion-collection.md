# ADR 0002. Notion 수집과 예약

상태: 채택

## 맥락

Notion 표의 속성 구성과 일정 분류는 소스마다 다르다. 도중에 페이지 조회가 실패해도 마지막으로 완성된 자료와 수집 예약이 보존되어야 한다.

## 결정

- 같은 Notion 표를 여러 표시 소스에 연결하면 수동 수집 또는 같은 예약 회차에서 스키마·행 페이지·하위 표·속성 상세 응답을 요청별로 한 번 읽는다. 각 연결은 그 응답을 자기 칼럼과 분류 규칙으로 변환하고, 자기 실행권으로 스냅샷을 확정한다. 한 연결에만 필요한 칼럼이 사라지면 그 연결의 마지막 정상 자료를 유지한다. 공유 응답은 해당 회차에서 같은 원본의 마지막 연결을 처리한 뒤 해제한다. 같은 원본과 재시도 단계의 정기 예약은 가장 늦은 도래 시각에 함께 실행하며, 변경된 매핑의 즉시 수집과 진행 중인 실행권은 독립적으로 처리한다.
- 소스별 속성 ID로 업무·일정·휴가를 내부 모델로 정규화한다. 목록 소스에서 하위 표 수집을 선택하면 `parentTitleProperty`로 부모 표를 연결하고, 하위 표 전체를 부모 소스 단위로 한 번에 확정한다. 기존 `roundTitleProperty` 연결도 읽는다. 부모 제목이 필요한 경우 상세 페이지까지 읽으며, 부모 항목이 중복되거나 상세 조회가 실패하면 마지막 정상 수집을 보존한다.
- `수집 소스`는 맨 위 ‘연결한 표’ 목록에서 연결을 고르고, 아래 연결 카드에서 편집한다. **찾기…**는 Notion 검색 API를 데이터 소스로 걸러 연동에 공유된 표를 최근 편집 순으로 최대 300개 보여 주며, 고르면 그 ID로 바로 칼럼을 조회한다(`NotionCatalog.tables`, `GET /v1/source-settings/tables`). 새 연결은 칸 종류로 표 종류(상태 칸이 있으면 할 일, 날짜만 있으면 일정)와 제목·상태·마감일·일정 기간 칸을 미리 고른다. 사람 칸은 본인 ID 설정이 필요해 미리 고르지 않는다. 저장된 연결의 선택은 바꾸지 않는다. 화면 용어는 수집 방식 → 표 종류(할 일·일정·휴가 승인), 원본 칼럼 → 칸, 소스 제거 → 연결 해제로 쓴다.
- Notion 원본 표 주소나 데이터 소스 ID를 직접 입력해 칼럼을 조회할 수도 있다. 페이지 안에 여러 원본 표가 있으면 수집할 표를 고른다. 다른 표나 차시 구조를 선택하면 역할·상태 분류·카테고리 칼럼의 연결을 다시 정한다. 같은 표를 다시 조회하면 편집 중인 연결을 유지한다. 일반 표는 데이터 소스 ID와 칼럼 ID를 저장한다. 차시별 수집 모드는 모든 하위 표에서 이름과 타입이 일치하는 칼럼을 사용한다. 앱에서 여는 주소는 수집 참조와 별도로 바꿀 수 있다.
- 목록의 조회 구분은 소스에 연결한 사용자 카테고리를 따른다. 일반 표·하위 표 구조는 별도로 선택한다. 새 하위 표 연결은 부모 제목 표시와 정렬을 기본으로 끈다. 부모 제목 표시, 부모 숫자 칼럼 또는 제목에서 ‘차’ 앞 숫자를 읽는 정렬을 각각 설정할 수 있다. QA에서 부모 제목 표시를 켜면 차시 필터와 완료 차시 제외 조건은 정렬 방식에 관계없이 부모 제목 전체를 비교한다. 기존 하위 표 연결은 제목 표시와 첫 숫자 정렬, 기존 스냅샷의 매핑 해시를 유지한다. 표를 다시 조회했을 때 연결된 숫자 칼럼이 없으면 설정 화면에 누락된 이름을 표시한다. 사용자가 정렬 방식을 바꾸거나 해제할 때까지 그 연결을 보존한다. 저장된 표를 처음 조회할 때도 조회 직전에 편집한 부모 정렬과 제목 표시 선택을 유지한다. 원본 숫자나 추출값이 비어 있으면 부모 정렬에서 마지막에 둔다.
- 수집 방식은 사용자가 등록한 카테고리 이름과 독립적으로 고른다. 목록은 제목과 선택한 담당자·상태·기한을 사용한다. 일정은 제목과 시작·종료 날짜를 사용하며 원본 분류, 참여자, 취소 여부를 추가로 연결할 수 있다. 차시별 하위 표는 목록에서 사용한다. 기존 소스는 저장된 매핑과 수집 기준을 이어받는다.
- 업무·QA 소스에서는 상태 칼럼을 연결하면 원문 값을 수집한다. 소스에서 편집한 완료값(`completedStatuses`)은 메인 목록의 표시 규칙에서 사용한다. 같은 표·수집 구조·상태 칼럼을 유지한 채 이름이나 다른 연결을 편집하면 이 값을 그대로 보존한다. 표나 구조를 바꾸거나 상태 칼럼을 교체·해제하면 이전 완료 기준을 제거한다. 일정 유형과 휴가 승인 값은 원본 칼럼의 옵션별로 편집한다.
- 카테고리의 값 종류는 텍스트·숫자·날짜·시간·참/거짓이다. `columnMappings`에는 원본 속성의 ID와 타입을 소스별로 저장한다. 저장된 이전 연결은 같은 원본 타입을 계속 사용한다. 참여자·상태·선택과 같은 Notion 속성은 텍스트 칼럼에도 연결할 수 있다.
- 시간 칼럼은 서울 시간의 시·분을 표시하며 날짜 전용 값의 시간은 비워 둔다. 날짜 칼럼은 캘린더의 표시 기준으로 사용할 수 있다. 숨긴 칼럼도 날짜와 알림에서 사용할 수 있도록 수집한다. 표시 대상이 바뀌면 정기 수집을 앞당긴다.
- 수집 소스를 저장할 때 등록된 카테고리를 선택해야 한다. 이전 문서에 남은 미지정 소스는 설정에서 수정할 수 있으며, 지정할 때까지 수집·조회·알림에는 사용하지 않는다.
- 사용자가 사람 칼럼을 연결하지 않은 새 소스는 해당 표 전체를 관리자용 메인 화면과 달력에 표시한다. 본인 업무 MCP 조회와 사람 기준 알림은 연결된 사람 칼럼이 있을 때만 사용한다.
- 프로바이더별 스키마 조회와 수집을 별도 계약으로 주입한다. Notion 설정의 칼럼 탐색과 업무 행 수집은 별도 어댑터로 두고, HTTP 요청 간격·커서·하위 표 탐색은 같은 읽기 모듈을 사용한다. 현재 등록된 프로바이더는 Notion이며 기존 문서에 `provider`가 없으면 Notion으로 읽는다. 새 연결과 변경된 매핑은 저장 전에 조회한 스키마로 검증한다. 연결이 바뀌면 다시 시작한 뒤 수집한다.
- 목록과 필요한 상세 속성의 페이지네이션이 끝나야 성공으로 처리한다. 응답 배열은 원래 순서대로 한 항목씩 꺼내 소비자에게 넘긴다. 처리한 행에 붙은 상세 원문을 같은 페이지의 나머지 행을 읽는 동안 보관하지 않도록 한다. 한 행의 속성은 디코딩한 ID로 한 번 색인하고, 역할과 저장 칼럼이 같은 속성을 가리키면 해당 행의 상세 조회 결과를 공유한다. 내장 값이 완전한 단순 제목·사람 목록은 재사용하고 참조 제목과 잘릴 수 있는 속성은 전체 조회한다. 반복 커서·중복·권한·매핑 오류는 부분 성공으로 바꾸지 않는다.
- 일정은 `category`·`eventTypes`로 회의·휴가·기타를 분류하고 `cancelled`로 취소 근거를 저장한다. 잘못된 취소 속성은 미취소로 취급하지 않는다. 휴가 분류와 승인 판정은 별개다.
- 수집 유스케이스는 원천 응답을 기다리는 동안 60초마다 현재 실행권을 갱신한다. SQLite 저장소는 짧은 독립 트랜잭션에서 아직 만료되지 않은 현재 세대·실행 ID·진행 상태를 확인한 뒤 실행권을 현재 시각 + 300초로 연장한다. 고정 5분만 허용하면 긴 페이지·하위 표 수집이 매번 폐기되므로 수집 시간과 중단 후 인계 시간을 분리한다. 갱신 실패나 취소 시 원천 작업을 취소하고 회수하며, 실행권 상실과 저장 장애를 구분해 반환한다. 프로세스 중단으로 갱신이 멈추면 마지막 갱신 후 300초에 다음 세대가 인계한다. 만료되거나 교체·종료된 실행은 갱신할 수 없고 이전 세대의 결과·실패는 새 세대를 변경하지 않는다. 절전·이벤트 루프 정지 등으로 만료를 넘기면 실행권을 부활시키지 않고 다음 수집에서 복구한다. 스키마 변경은 필요 없다.
- 실행권의 세대와 만료를 확인해 오래된 실행의 결과를 막는다. 스테이징 자료와 스냅샷·변경 이력·알림을 함께 확정한다. 수집 실패 시 마지막 정상 자료를 보존하고 처음 누락된 행만 `unconfirmed_missing`으로 바꾼다. 업무 변경 비교에는 이번 수집에 포함된 ID의 이전 원문을 묶어서 읽는다. 누락 후 다시 나타난 업무도 마지막 정상 값과 비교한다. 매핑이 바뀌면 이전 스냅샷을 새 연결에 사용하지 않는다. SQLite 직렬화 모듈에서 소스의 업무 의미를 결정하는 필드만 골라 매핑 해시를 계산한다. 항목은 유형별 저장 필드를 한 행씩 직렬화한다. 비어 있는 선택 칼럼을 생략해 기존 JSON 바이트와 의미 해시를 유지한다.
- 소스별 다음 실행 시각·재시도 횟수는 SQLite에 저장한다. 예약 실행기는 현재 소스의 예약 시각과 실행권 만료 시각을 한 번에 읽는다. 실행할 소스가 없으면 쓰기 트랜잭션 없이 대기한다. 기한이 된 소스는 설정 순서대로 처리하고, 실행권을 얻는 트랜잭션 안에서 기한과 만료를 다시 확인한다. 상태를 조회할 때 현재 세대의 실행 이력을 연결해 성공·실패 건수를 집계한다. 진행 건수는 이력이 `running`이고 실행권 만료 시각이 조회 시각보다 뒤인 소스만 센다. 만료 경계에서는 예약의 실행 가능 판정과 동일하게 진행 중에서 제외하며, 실행권이 없으면 진행 중으로 세지 않는다. 한 응답의 진행 건수와 다음 실행 시각은 같은 시각을 기준으로 계산한다. 조회는 만료 이력·실행권·예약을 수정하지 않으며, 중단된 이력의 정리는 다음 세대 획득에서 수행한다. 수동·예약 명령은 같은 조립부에서 원천, 스냅샷 저장소와 업무·회의 알림 정책을 받는다. 예약 실행에만 도래 시각 확인과 빠른 재시도 정책을 주입한다. 기본 15분이며 `collection_preferences`가 환경 기본값보다 우선한다. 재시작·절전 복귀 시 밀린 예약은 한 번 실행한다. 주기 변경은 예약과 함께 저장하고 진행 중인 실행권을 유지한다.
- 수동 `sync`는 성공·실패 건수와 함께 유효한 실행권 때문에 실행 중인 소스 수, 더 최신 관측으로 건너뛴 소스 수를 각각 출력한다. 모두 성공하면 종료 코드 0, 실패 또는 건너뜀이 있으면 1을 반환한다.
- 네트워크·시간초과·요청 제한은 15·30·60초 간격으로 최대 세 번 빠르게 재시도한다. 서버의 대기 지시를 반영한다. 인증·권한·매핑 실패는 정기 주기로 돌아간다. 지연 기준은 UI에서 보정한 시각 대신 실제 저장된 다음 예약 + 5분이며 예약 없는 수동 자료에만 최대 유효시간을 적용한다.

- 소스 편집 시 목록·일정·휴가 역할을 초기 템플릿으로 사용한다. 역할을 저장할 때 `columnRoles`에 ID·이름·허용 타입을 기록하고 `properties`에서 원본 칼럼을 연결한다. 기존 문서는 같은 템플릿으로 해석한다. 사용자 역할은 UUID로 식별하고 선택한 타입의 값을 스냅샷에 저장한다. 이름을 바꿔도 사람 범위·기간·승인 계산에 쓰는 역할 ID와 기존 값의 키를 유지한다.

## 결과와 검증

저장 호환성은 `tests/integration/sqlite/test_snapshots.py::test_stored_json_and_hash_remain_compatible`에서 업무·일정·휴가의 기본값과 선택 칼럼을 실제 SQLite에 저장한 뒤 JSON 바이트와 의미 해시로 확인한다. #29의 `dc5847e`에서 추가한 빈 `parent_label`·`parent_order`는 직전 저장 형식에 없으므로 검사 기대값에서도 생략한다. 모델의 `asdict` 결과를 맞추려고 저장 구현에 두 null 필드를 추가하면 기존 JSON과 해시가 달라진다. 예약 계산값 `alert_due_at` 역시 스냅샷에 포함하지 않는다.

사용자는 실패 후에도 마지막 정상 자료와 지연 근거를 볼 수 있다. 보관 확인값은 수집 차단 조건으로 쓰지 않는다. `src/infrastructure/notion/`, `src/infrastructure/sqlite/snapshots.py`, `src/infrastructure/sqlite/schedules.py`, `src/application/periodic.py`에서 구현한다. 실행권 갱신과 원천 작업 회수는 `src/application/use_cases/synchronize.py`와 `SnapshotStore.renew_run` 계약으로 연결한다. 임시 저장소에서 차시 일부 실패·실행 중단·정상 복구와 재시도 예산을 확인한다. `tests/integration/sqlite/test_collection_lease.py`는 가상 원천과 주입한 시계로 수동·예약 장시간 수집, 경쟁 획득 차단, 만료 경계 인계, 이전 세대 거부, 부분 실패 보존, 갱신 저장 오류와 취소 정리를 확인한다. 실제 회사 연동과 배포 앱 검증은 별도로 수행한다.

`tests/integration/sqlite/test_schedules.py::test_status_counts_only_current_unexpired_lease`는 임시 SQLite와 주입한 시계로 만료 직전·정확한 만료 시각·만료 후의 진행 집계와 예약 판정을 비교한다. 상태 조회 전후 실행 이력·실행권·예약 행의 보존, 다음 세대 획득 뒤의 집계와 정상 종료·실패 집계도 확인한다.
