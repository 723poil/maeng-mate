# ADR 0008. 영속 알림과 macOS 전달

상태: 채택

## 맥락

앱 재시작이나 출근·일정 변경에도 예약·전송 결과를 보존하고, 같은 알림을 채널별로 안전하게 전달한다.

## 결정

- 같은 Notion 표를 여러 표시 설정에 연결하면 각 설정이 독립적으로 알림 조건을 평가하고 예약을 취소할 수 있다. 같은 표·항목·규칙에서 관측한 같은 변경이나 같은 시각의 예약은 전달 키를 공유한다. 각 설정에서 허용한 채널에 한 번씩 전달하며, 한쪽의 예약을 취소해도 다른 쪽의 유효한 예약은 남는다. 수집 오류는 같은 표를 읽은 시도의 시작 시각과 오류 코드로 묶는다. 이전 예약의 채널별 접수·결과 미확인 기록은 새 키에서도 재사용한다.

- 일정 소스의 공통 알림 조건에서 ‘일정 분류 (수집 소스)’를 선택하면 수집 규칙을 적용한 최종 분류명을 비교한다. 새 일정 표의 기본 유형은 기타이며, 기존 표에 생략된 기본 회의 유형은 설정 이전 때 명시해 예약 식별자를 유지한다.

- 알림 발신 앱의 이름·아이콘은 앱 기본값(Catch, 앱 아이콘)으로 고정하고 설정에서 바꾸지 않는다. 메뉴바 시작과 매 발송 전에 기본값을 적용하므로, 예전 버전에서 바꾼 이름·아이콘이 저장돼 있어도 기본값으로 돌아간다. 저장된 `notificationIdentity` 값은 백업·설정 형식 호환을 위해 남기지만 읽어 적용하지 않는다. 기본값을 쓰는 설치본은 실제 번들 아이콘을 비교해 새 도안을 반영한다. 설정의 알림 페이지에는 권한과 발신 앱 준비를 확인하는 ‘알림 확인’만 둔다.

- 새 본인 일정·업무와 QA의 배정·상태·기한 변경은 정상 스냅샷 확정과 함께 예약한다. 첫 수집과 매핑 변경은 비교 기준만 저장한다. 재수집에서는 같은 소스·사용자의 미전달 업무 알림을 한 번 읽고 비교한다. 현재 사실과 달라진 실행권은 무효화하고 대기 중인 제목·주소는 변경된 경우만 갱신한다. 일시 누락은 삭제·새 배정 근거로 사용하지 않는다.
- 기존 본인 참석 회의 규칙의 10분은 연결된 일정 칼럼의 시작 전 분 값으로 이전한다. 재수집할 때는 회의 키로 미전달 예약을 묶어서 읽고, 시작 시각이나 매핑이 달라지면 이전 실행권을 무효화한다. 대기 중인 예약의 본문과 주소는 값이 달라졌을 때만 갱신한다. 취소·시각·참석자·현재 가용성과 만료를 다시 확인한다. 종일 일정·휴가·시작한 회의는 제외한다. 소스·매핑별 수집 장애는 복구 전 한 번 표시하고 복구하면 미전달 작업을 취소한다.
- 퇴근 알림은 사용자가 직접 입력한 분에만 예약한다. 신규 설정은 빈 목록이다. 시각을 바꾸면 설정 저장과 같은 트랜잭션에서 오늘 기록을 읽어 남은 예약을 맞춘다. 실제 퇴근·휴가·정정에 따라 미전달 예약을 취소하거나 갱신한다. 상주 앱 시작 시 오늘의 미래 예약만 보완한다. 기존에 저장한 분 단위 구독 키를 화면·예약·발송 직전 검증에서 함께 사용한다. 새 일정 알림의 만료 기준도 도메인에서 계산하고 SQLite가 트랜잭션 안에서 예약을 반영한다.
- 논리 작업(`notification_jobs`)과 채널별 전달(`notification_deliveries`)을 구분한다. 새 작업에 전달 채널을 배정할 때 구독 설정을 읽는다. 전송 직전에는 유효한 실행권에 대해 현재 사실과 최신 구독을 같은 읽기 트랜잭션에서 확인하고, 전달 결과를 저장한다. 빈 큐를 확인할 때마다 발신 아이콘이 포함된 설정 문서를 읽는 비용을 줄인다. 구독을 끄면 보류 작업과 발송 승인을 취소한다. 주기적인 취소·만료 정리는 대기 전달의 예약 ID로 해당 작업만 조회한다. 전달 결과는 `requested`(접수), `failed`(실패), `unknown`(결과 미확인), `cancelled`(취소)로 구분하며 HTTP와 저장소에서 같은 계약으로 검증한다. 요청됨·결과 미확인 상태는 재실행 시 자동 재전송하지 않는다.
- `알림`은 저장된 카테고리 규칙을 표시한다. 소스 연결이나 수집 이력이 없어도 구독을 설정할 수 있다. 새 설치의 전체 알림·전달 채널·구독 목록은 모두 꺼짐 또는 빈 상태다. 카테고리의 종류 선택, 전체 채널, 소스별 선택을 발송 시각과 직전에 확인한다. 카테고리 선택이 없으면 이전 전체 종류 선택을 이어받는다. 알림을 끄면 실행 대기 중인 채널 전달은 같은 트랜잭션에서 취소하고, 미래 예약은 발송 시점의 선택을 따른다.
- `카테고리 → 설정… → 알림 규칙`에서 저장 칼럼에 값 변경, 특정 값으로 변경, 값이 비워짐 조건을 등록한다. 규칙은 선택한 칼럼을 연결한 소스에서 실행한다. 이전 소스별 규칙은 기존 적용 범위를 유지한다. 처음 본 값은 비교 기준만 기록한다. 수집이 끝나면 변경 판정·알림·스냅샷을 같은 트랜잭션에서 확정한다. 규칙별로 이번 수집에 나타난 항목의 이전 값만 읽는다. 목록에서 빠진 항목은 미전달 예약을 함께 취소하고 비교 기준은 보존해 다시 나타날 때 마지막 값과 비교한다. 관측했지만 담당 범위를 벗어나거나 비교값이 사라진 항목은 기준도 제거한다. 규칙 조건을 변경하거나 끄면 해당 소스의 이전 예약과 기준을 무효화한다.
- 새 규칙은 카테고리의 저장 칼럼 또는 수집 상태를 입력으로 선택한다. 사람 속성에는 내 계정 또는 지정한 Notion 사용자 ID가 새로 포함되는 조건을 설정할 수 있다. 수집 상태는 모든 실패 또는 특정 오류 코드를 선택한다. 각 규칙의 ID로 문구·채널·실행권을 구분한다. 개인별 소스 이름이나 칼럼 ID를 코드에 넣지 않는다.
- 알림 규칙 편집 시트에서 공통 저장 칼럼의 조건과 표별 원본 속성 조건을 편집한다. 원본 조건에는 데이터 소스 ID와 속성 ID를 저장한다. 편집기는 소스 연결에 기록된 속성명을 먼저 표시하고 표 조회가 끝나면 최신 이름으로 갱신한다. 이름을 확인할 수 없으면 미확인 상태로 표시한다. 하위 표마다 ID가 다른 QA 차시에서는 공통 속성 이름을 각 하위 표의 ID로 해석한다. 포함 조건은 모두 일치 또는 하나라도 일치로 결합하고 제외 조건은 하나라도 맞으면 제외한다. 칼럼 조건이 없으면 소스의 기존 범위를 사용한다. 수집 실패는 항목이 없어 이 설정을 제공하지 않는다.
- 숨긴 칼럼도 조건에서 참조하면 수집하고 텍스트는 전체 값으로 비교한다. 비교 칼럼을 연결하지 않은 소스에서는 해당 규칙을 실행하지 않는다. 상대 날짜는 서울 기준으로 변경 알림은 관측일, 예약 알림은 발송 예정일에 평가한다. 조건이나 칼럼 연결이 달라지면 이전 기준과 대기 예약을 무효화한다. 종전 회의 규칙은 표의 분류 속성에 연결된 실제 선택값들을 포함 조건으로 옮긴다. 분류 속성 없이 표 전체가 회의였으면 표 연결만 남긴다. 예정 일정은 원본 날짜 속성의 종료 시각을 검사한다. 대응하는 표가 없으면 규칙을 끄며 사용자가 새 표를 연결할 수 있다. 같은 조건으로 이전한 규칙은 기존 비교 기준과 예약 키를 이어 쓴다.
- 이전 이벤트 문서는 서버 시작 시 쓰기 잠금 안에서 한 번 변환한다. 소스의 실제 역할→원본 속성→카테고리 칼럼 연결을 따라 규칙을 만들고, 소스별 연결이나 구독이 다르면 적용 범위를 나눈다. 연결되지 않은 조건은 이름을 보존한 비활성 규칙으로 남겨 사용자가 직접 연결할 수 있게 한다. 이후 편집과 발송은 저장된 칼럼·조건·값을 사용한다. 이전 형식의 대기 건은 원본 소스에 연결된 이전 규칙의 문구와 채널을 사용한다. 조건이 바뀌면 그 소스의 옛 대기 건과 실행권도 함께 무효화한다. 배정·상태·기한의 비교 기준은 같은 매핑의 기존 스냅샷에서 이어받고 신규 설치에는 규칙을 추가하지 않는다.
- 날짜·시간 칼럼에는 전날 또는 당일의 서울 시각, 시작 시각을 기준으로 한 분 단위 사전 알림을 지정할 수 있다. 구간은 원본의 시작값을 사용한다. 시각이 없는 날짜에는 분 단위 사전 알림을 만들지 않는다. 첫 수집에서도 미래 시각을 예약하고, 정상 재수집에서 값·대상·가용성이 달라지면 이전 실행권을 무효화한다. 같은 규칙·항목·예정 시각의 접수 결과는 재사용해 중복 전달을 막는다. 날짜 예약은 해당 서울 날짜가 끝날 때, 사전 예약은 시작 시각에 만료된다. 0분 전은 시작 후 1분 동안 전달할 수 있다. 유효한 원본에서 계산한 예정 시각이나 만료 경계가 날짜 표현 범위(1~9999년)를 벗어나면 해당 규칙의 예약을 생략한다. 서울 날짜를 표현할 수 없는 UTC 시점도 원본과 시간대를 보존한다. 시작 전 분 단위 예약은 UTC에서 계산하고, 서울 기준일이 필요한 상대 날짜 조건은 기준일이 없으면 일치하지 않는다. 원본 행과 다른 규칙은 정상 스냅샷에 반영하며, 원본 형식 오류와 수집 실패의 처리는 기존 정책을 따른다.
- 규칙은 표시할 때 잘린 값 대신 원본 비교값의 해시를 사용한다. 시간의 초와 이름이 생략된 사람의 식별자는 비교에서 유지한다. 알림에는 규칙 이름, 항목 제목과 원본 링크를 사용한다. 직접 만든 규칙은 카테고리별 알림 탭에서도 개별 선택할 수 있다.
- 규칙별 본문과 채널은 카테고리 문서의 `delivery`에 저장한다. 새 규칙은 빈 문구와 빈 채널로 시작한다. 개별 설정이 없던 규칙을 열면 실제 적용 채널과 항목별 동적 본문을 입력란에 표시한다. 문구 아래에는 현재 규칙의 본문 변수를 표시하고, 클릭하면 편집 위치에 삽입한다. 문구와 채널은 각각 편집할 수 있고, 저장해 둔 일반 텍스트에 포함된 중괄호는 원문으로 보존한다. 전체·카테고리·규칙에서 함께 허용한 채널만 전달한다. 여러 업무 조건이 한 번에 바뀌면 각 채널에 허용된 규칙의 이름과 문구를 한 건으로 모은다. 발송 직전에 현재 선택을 다시 검사하며 문구나 대상을 바꾸기 전의 실행권을 취소한다.
- 배포 앱에는 알림 발신 앱을 ZIP으로 동봉한다. 설치할 때 지원 폴더에 풀어 LaunchServices가 동봉 원본을 같은 발신자로 선택하는 일을 방지한다. 번들 검사는 임시 폴더에 복원한 앱의 식별자와 실행을 확인한다.
- 발신 앱을 처음 준비할 때 현재 설치 경로를 등록한다. 같은 식별자로 검색되는 구형 배포 앱 내부와 배포 빌드 중간 폴더의 발신 앱은 LaunchServices 등록만 해제한다. 앱 파일과 알림 권한은 유지한다.
- 메뉴바 작업자는 인증된 큐를 통해 `NotificationSender`를 호출한다. macOS 발신 앱은 고정 번들 식별자를 사용하고 제목·본문을 stdin으로 받는다. OS 권한 요청은 사용자가 누른 알림 확인에서 시작한다. OS 접수와 실제 배너 표시는 구별한다.
- 업무·QA·일정·회의는 검증한 원본 URL을 별도 필드로 보관한다. macOS에서는 기본 클릭에서만 열고, 클릭으로 알림 번들이 재실행된 경우도 처리한다. Slack에서는 제목을 구조화 링크로 만든다. 원본 없는 퇴근·테스트 알림은 주소를 추측하지 않는다. [ADR 0009](0009-slack.md)

- 퇴근 예정이 서울 기준 기록일의 자정 이상이면 자동 퇴근 알림을 예약하지 않는다. 사전 알림 시각이 기록 당일이어도 같으며, 기록 저장·근무 규칙 변경·알림 설정 변경·시작 시 보완은 공통 예약 함수의 당일 판정을 사용한다. 기존 미전달 예약은 무효화하고 접수 이력은 보존한다. 규칙을 바꿔 다시 당일 예정이 되면 미래 예약만 복구한다.

- 알림 실행기는 처리 여부와 채널 실패 여부를 별도로 반환한다. 메뉴바 작업자는 정상 요청·취소를 확정한 뒤 다음 한 건을 즉시 확인하고, 빈 큐·채널 실패·연결 예외·복원 확정 대기에는 종료 신호로 중단할 수 있는 5초 대기를 둔다. 매 반복에서 종료와 복원 상태를 다시 확인하며 외부 발송을 병렬화하거나 실패한 실행권을 자동 재전송하지 않는다. 채널이 없는 논리 예약은 각기 짧은 트랜잭션에서 정리한 뒤 다음 예약을 확인해 빈 큐로 오인하지 않는다. 구현은 `src/application/notifications.py`, `src/bootstrap/notification_worker.py`, `src/infrastructure/sqlite/notifications.py`다.

## 결과와 검증

임시 DB·인증 루프백 API와 격리 개발 앱에서 동시 도래 전달의 간격, 발송 직전 구독 변경, 실패·응답 유실·재시작·종료·복원 대기를 확인한다. 외부 채널의 응답 시간과 진행 중 요청의 종료 제한은 그대로 따른다.

채널별 실패가 다른 채널의 결과를 덮지 않는다. `src/infrastructure/sqlite/notifications.py`, `notification_deliveries.py`, `src/infrastructure/notification_app/agent.py`, `src/bootstrap/notification_channels.py`에서 구현한다. 임시 큐에서 실행권 충돌·정정·재시작을 확인하고 macOS에서 실제 배너 클릭을 확인한다.
